Monicomm · how it's built

Tech stack and app flow

Three Docker deployments on a closed network. Collectors touch the devices. Monicomm holds the data, the UI and the local AI, with no internet and a firewall between it and the devices. Snapshot of main on 25 Nov 2026, after PR #2 (collector servers).

Where data flows

Device data enters through the two collector servers, crosses into Monicomm over mutual TLS and ends up in Postgres. Users only ever talk to web. A path back toward the devices, the configurator for human-approved changes, is planned for phase F and not built.

What crosses into Monicomm

Three event types, defined in collector/README.md. Each is a JSON object with schema, kind and collector_id. A schema change means a new version (.v2). Vendor parsing and MIB name translation happen in Monicomm, not on the collectors.

One question, end to end

How a Chat AI answer is made. The model never reads the database directly. It asks api to run a small read-only tool, and every answer carries the row IDs it came from. Investigator, Analyzer summaries and change impact reports work the same way.

The six modules on this stack

All six share one database and one model. Each owns its own folder in api/app/modules/ and web/src/features/, with its accent color from the design system.

From a laptop to the closed network

Code is written and tested on connected machines. Only a checked bundle crosses into the closed network.

  1. Own branch

    Named after your GitHub username, for example amit0604/feat-mapper-lldp.

  2. Pre-push hook

    Air gap, ruff, pytest, prettier, eslint, stylelint, tsc, vitest, build.

    Fails: push cancelled

  3. GitHub Actions

    Same checks, then the Docker smoke test with the no-internet probe.

    Red: can't merge

  4. Pull request

    One reviewer. UI changes need light and dark screenshots.

  5. main

    Always deployable. Squash-merged.

  6. Offline bundle

    Images, models and checksums carried in on approved media, then docker load and compose up.

Rules to settle

The configurator isn't built yet, but the plan still says it will change devices after a human approves, and CLAUDE.md rule 3 says never write code that changes device config. Settle this in the phase F ADR. Branch protection on main also isn't on yet, so step 3 doesn't block a merge until someone sets it in GitHub.
